# 提交并进入下一条

## 请求标识 / 目的

`POST /web-task-alone-api/task/piece/execute`

用于提交当前分段标注结果。页面中的“提交进入下一条”和“提交并退出”由平台原生流程组织后续导航。

## 页面入口 / 触发动作

- 页面：`/workbench/piece/mark.html?taskId={taskId}&executeClass=TAG_PIECE`
- 触发：用户点击外层页面的 `.submit` 或 `.submit_finish` 原生按钮。

## 请求摘要

- 方法：`POST`
- 内容：当前任务上下文、有效性、已上传标注引用、质检结果和摘要。
- 后续首版不直接调用该接口，只观察结果并使用平台原生按钮完成提交和导航。

## 请求体摘要

| 字段 | 职责 |
|---|---|
| `taskId` | 当前任务标识 |
| `dataId` | 当前数据条目标识，用于严格对题 |
| `isValid` | 当前条目整体有效性 |
| `executeClass` | 当前执行类型 |
| `tagRecord` | 已上传 annotation JSON 的记录或引用 |
| `qualityResult` | 平台质检结果或其引用 |
| `summary` | 本次执行摘要 |

只记录字段职责，不固化真实值、对象地址或完整业务载荷。

## 响应摘要

成功响应由页面原生逻辑消费：提交进入下一条时重新初始化下一条数据，提交并退出时结束当前执行流程。具体响应字段和导航条件以未来脱敏样例为准。

## 关键字段

- `taskId + dataId + executeClass` 用于确认提交对象与当前页面一致。
- `tagRecord` 必须对应平台刚完成上传的当前 annotation JSON。
- `isValid` 与段落级 `formResult.isEffective` 含义不同，不得互相推导。

## 前端接入建议

- 后续扩展只在用户明确触发后点击唯一、可见、可用的原生提交按钮。
- 点击前等待平台自动暂存完成，并再次校验当前条目与预览确认时一致。
- 提交后以路由或新条目上下文变化确认已进入下一条；未确认时停止，不重复点击。

## 风险 / 未确认项

- `.submit` 与 `.submit_finish` 的完整响应差异及失败提示尚未以脱敏样例确认。
- 直接重放接口可能绕过平台校验、暂存和导航状态，因此当前边界明确禁止。
- 页面原生按钮的禁用态、重复提交保护和超时行为需在真实安全测试条目中验收。
